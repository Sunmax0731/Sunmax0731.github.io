# Local Deck Builder

`data/pokemon-tcg-ai-battle.zip` を読み、デッキを複数管理するブラウザアプリです。
Competition DataをGit管理対象へコピーせず、ローカルAPIまたはブラウザ内ZIP読み込みでZIP内のCSVとPDFを参照します。

## 必要なアプリ

- Node.js 22以降
- npm

この環境では `node v24.14.0` と `npm 11.9.0` で確認しています。

## 1クリック起動

リポジトリルートの `start-deck-builder.cmd` をダブルクリックしてください。

初回起動時は `tools/deck-builder/node_modules/` を作るため、`npm install` が実行されます。
起動後、ブラウザで次を開きます。

```text
http://127.0.0.1:5173
```

## コマンド起動

```powershell
cd tools/deck-builder
npm install
npm run dev
```

## データ配置

ローカル開発サーバーでは、標準で次のファイルを自動読み込みします。

```text
data/pokemon-tcg-ai-battle.zip
```

別のZIPを使う場合は、環境変数 `PTCG_DATA_ZIP` を指定します。

```powershell
$env:PTCG_DATA_ZIP="D:\path\to\pokemon-tcg-ai-battle.zip"
npm run dev
```

## 静的ホスティングでの使い方

GitHub Pagesなど、サーバーAPIを置けない環境では、アプリ画面上部の `ZIP読込` または画面へのドラッグ&ドロップで、手元の `pokemon-tcg-ai-battle.zip` を読み込みます。

この方式ではCSV/PDFはブラウザ内で展開され、サーバーへアップロードされません。
ZIP、CSV、PDF、カード画像をGitHub Pagesやリポジトリへ配置しないでください。

本ツールにはカードデータ、Kaggle Competition Data、カード画像、公式ロゴ、公式カード本文、チーム固有の戦略、実デッキ例、スコアリング設定は含まれていません。
利用者は各自でKaggleのRulesに同意し、自分の環境で取得したZIPを読み込ませる前提です。

## データとプライバシー

- 読み込んだZIP、CSV、PDF、カード情報、デッキ内容は外部サーバーへ送信しません。
- ブラウザ内のFile API、Blob URL、PDF.jsで処理します。
- Analytics、Sentry、外部API、ログ収集SDKはこのアプリには組み込みません。
- デッキ名、カードID、枚数、方針、役割、メモ、変更履歴はブラウザの `IndexedDB` に保存されます。
- 旧版の `localStorage` 保存データがある場合は、初回読み込み時に `IndexedDB` へ移行します。
- 保存データを削除する場合は、ブラウザのサイトデータ削除機能でこのサイトの `IndexedDB` を削除してください。

## 機能

- OSの言語設定に応じた日本語/英語の初期表示
- 表示言語の手動切り替え
- ZIP内CSVをもとにしたカード検索
- ZIPファイルのドラッグ&ドロップ読み込み
- カード種類、タイプ、HP範囲、エキスパンション、進化段階、ルール、弱点、抵抗力、にげる、特性、ワザ情報、投入枚数によるフィルター/ソート
- フィルター/ソートUIの表示・非表示切り替え
- リスト表示の列表示切替
- グリッド表示のカード情報表示切替
- ライブラリカードのクリック選択と、ドラッグまたは右ペイン操作によるデッキ投入
- ZIP内PDFを使った券面確認
- 複数デッキのローカル管理
- デッキ名変更とデッキ方針メモ
- カード別の役割とメモ
- 保存ごとの追加カード、削除カード、変更意図の履歴
- 公式 `deck.csv` 形式への書き出し
- 公式 `deck.csv` 形式の読み込み
- GitHub Issues共有用JSONの書き出し
- リスト表示での列幅ドラッグ変更
- ID、HP、タイプ、弱点、種類、進化段階、にげる列のヘッダークリックソート
- PDF内のCard ID別ページインデックス化
- PDF.jsによるカード券面ページのサムネイル表示
- 基本エネルギーを除く同名カード4枚上限の入力制限

## 保存場所

デッキはブラウザの `IndexedDB` に保存されます。
チーム内で提出用レシピを共有する場合は、アプリからCSVを書き出します。
競技レビュー用に方針、役割、メモ、変更履歴を共有する場合は、アプリから共有JSONを書き出し、GitHub Issuesへ添付します。

共有JSONにはカードID、枚数、方針、役割、メモ、変更履歴だけを入れます。
カード本文、カード画像、PDF、CSV本体は含めません。

提出用CSVは生成物です。
通常は `output/` または提出パッケージ内に置き、Git管理しません。
